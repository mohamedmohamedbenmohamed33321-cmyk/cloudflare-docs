You can now access realtime backlog size (in count & bytes) and `oldest_message_timestamp_ms`, useful for calculating backlog lag via the [Queues REST API](/api/resources/queues/methods/create/), and [Javascript API](/queues/configuration/javascript-apis/). You can also access realtime backlog lag in the Cloudflare dashboard on your queue's [Metrics tab](https://dash.cloudflare.com/?to=/:account/workers/queues/:queueId/metric).

### REST API

To access metrics via the REST API, use the new `metrics` endpoint: `/accounts/{account_id}/queues/{queue_id}/metrics` which returns `backlog_count`, `backlog_bytes` and `oldest_message_timestamp_ms`.



The following endpoints also now include a `metadata.metrics` object on the result field after successful message consumption:

- `/accounts/{account_id}/queues/{queue_id}/messages/pull`
- `/accounts/{account_id}/queues/{queue_id}/messages`
- `/accounts/{account_id}/queues/{queue_id}/messages/batch`

### Javascript APIs

Both `env.QUEUE.send()` and `env.QUEUE.sendBatch()` now return a `metrics` object, or you can use `env.QUEUE.metrics()` directly:

```ts
const {
    metadata: {
        metrics: {
         backlogCount: number,
         backlogBytes: number,
         oldestMessageTimestamp: number,
        }
    }
} = await env.QUEUE.send(...)
```

You can also query these fields via the [GraphQL Analytics API](/analytics/graphql-api/). For more information, refer to [Metrics](/queues/observability/metrics/).
